# STALZONE Server Blocker — настройка

## Файлы

- `main.cpp` — полный исходный код программы.
- `Servers.json` — группы серверов и адреса, встраиваемые в EXE.
- `fonts` — Orbitron и его лицензия, встраиваемые в EXE.
- `app.ico` — иконка, встраиваемая в EXE.

Внешние библиотеки C++ не требуются.

## Проект Visual Studio

1. Распакуйте архив в отдельную новую папку.
2. Откройте файл `StalzoneServerBlocker.sln`.
3. В верхней панели Visual Studio выберите `Release` и `x64`.
4. Выполните **Build → Rebuild Solution**.
5. Убедитесь, что в окне сборки указано `0 Errors`.
6. Готовый файл находится в `build\Release\StalzoneServerBlocker.exe`.

Все необходимые параметры уже записаны в `StalzoneServerBlocker.vcxproj`:

- стандарт `ISO C++20`;
- кодировка UTF-8 и набор символов Unicode;
- подсистема `Windows`;
- автоматическое использование установленного в вашей Visual Studio набора компилятора;
- встраивание `Servers.json`, Orbitron, лицензии и иконки в ресурсы EXE;
- статическая Release-сборка `/MT`;
- отключение создания `.pdb` в Release.

Новый исполняемый файл называется `StalzoneServerBlocker.exe` и создаётся в папке
`build\Debug` или `build\Release`.

У новой версии:

- в заголовке окна указано `StalzoneServerBlocker`;
- над списком находится надпись `SERVER TREE` цветом выбранной палитры;
- справа над списком находится подпись `by.Kwokwiy`;
- группы и вложенные серверы расположены вертикальным древом.
- невыбранные серверы имеют пустой контурный квадрат;
- пустой квадрат хранится как отдельная обычная иконка элемента дерева и поэтому отображается постоянно;
- квадрат внутри остаётся чёрным в тёмной теме или белым в светлой теме;
- рамка квадрата и маленькая строгая галочка используют текущий цвет палитры;
- галочки автоматически восстанавливаются только для IP, одновременно присутствующих в активных входящем и исходящем правилах нового формата;
- справа снизу находится расширенная кнопка `WHITE THEME`, включающая белую тему;
- кнопка `COLOR` меняет акцент на красный, зелёный, оранжевый, фиолетовый, розовый или голубой.
- выбранные тема и цвет сохраняются для текущего пользователя Windows и автоматически восстанавливаются после перезапуска программы или системы;
- декоративная обводка главного окна отключена;

Если этих надписей нет, запущена старая копия программы.

При запуске программа запрашивает права администратора, поскольку она управляет
общесистемными правилами брандмауэра Windows.

## Работа программы

- Древовидный список групп и серверов создаётся динамически из встроенного `Servers.json`.
- Если рядом с EXE вручную положить внешний `Servers.json`, программа использует его вместо встроенного. Это необязательный способ обновить список без перекомпиляции.
- При запуске программа читает свои действующие правила Firewall. Галочка восстанавливается только тогда, когда оба правила нового формата включены, имеют действие `BLOCK`, протокол `ANY`, охватывают все профили и содержат IP сервера.
- Отключённые, неполные и старые правила больше не создают ложных галочек.
- Правила Firewall сохраняются самой Windows, поэтому состояние галочек восстанавливается и после перезагрузки системы.
- Галочка на главной группе выбирает или снимает выбор со всех вложенных серверов.
- Каждый отдельный сервер можно отметить независимо.
- Кнопка `BLOCK SELECTED` блокирует только отмеченные галочками серверы и создаёт два глобальных правила брандмауэра Windows:
  - `STALZONE Server Blocker - ALL Outbound`
  - `STALZONE Server Blocker - ALL Inbound`
- Правила блокируют любой IP-протокол, все порты и оба направления для выбранных IP.
- Правила явно применяются ко всем сетевым интерфейсам, локальным адресам, программам и профилям брандмауэра.
- Перед применением программа проверяет каждый активный сетевой профиль. Если Брандмауэр Windows выключен для профиля, программа включает его и повторно проверяет состояние.
- Если системные службы фильтрации `BFE` или Брандмауэра Windows `MpsSvc` остановлены, программа запускает их. Если служба отключена, программа переводит её в автоматический запуск и затем запускает.
- Если службу или профиль нельзя включить из-за системной политики либо недостаточных прав, программа возвращает ошибку и не показывает ложное сообщение об успешной блокировке.
- После создания программа проверяет протокол, направление, действие, состояние и наличие каждого выбранного IP в обоих правилах. Проверка учитывает эквивалентные маски профилей и каноническую запись IPv4, которую может вернуть Windows.
- После успешного или неуспешного применения программа повторно читает свои правила Firewall и синхронизирует галочки с их фактическим содержимым.
- При ошибке окно показывает точный этап создания или проверки правила. Неполные правила автоматически удаляются.
- Уже открытые TCP-соединения с выбранными IP принудительно завершаются после применения блокировки.
- UDP не имеет состояния соединения, поэтому отдельного UDP-сеанса для принудительного закрытия в Windows нет. Все последующие входящие и исходящие UDP-пакеты к выбранным IP отбрасываются системным брандмауэром; отображение отключения происходит после тайм-аута самой игры.
- Правила брандмауэра продолжают действовать после закрытия программы.
- При переходе на новую версию старые четыре TCP/UDP-правила автоматически удаляются.
- Кнопка `REMOVE BLOCKS` удаляет только правила, созданные этой программой, включая старые имена правил.
- Другие существующие правила брандмауэра Windows не изменяются.

## Иконка программы

В проект уже добавлена готовая чёрно-красная иконка `SSB`:

- `app.png` — исходное изображение 1254×1254;
- `app.ico` — Windows-иконка с размерами 16, 24, 32, 48, 64, 128 и 256 пикселей;
- `StalzoneServerBlocker.rc` — ресурс, встраивающий иконку внутрь EXE.

### Быстрая замена иконки окна

1. Подготовьте настоящий файл значка Windows с именем `app.ico`. Простое переименование PNG в ICO не подходит.
2. Поместите `app.ico` рядом с `StalzoneServerBlocker.exe`.
3. Перезапустите программу.

Программа автоматически использует этот файл для окна и панели задач. Если внешнего файла рядом с EXE нет, используется встроенная иконка.

### Замена встроенной иконки EXE

1. Замените существующий `app.ico` в корне проекта новым ICO-файлом с тем же именем.
2. Выполните **Build → Rebuild Solution**.

После встраивания иконка будет отображаться и у самого файла `.exe` в Проводнике. Для хорошего качества ICO должен содержать размеры 16×16, 32×32, 48×48 и 256×256.

## Сборка для другого компьютера

1. Распакуйте эту версию проекта в новую папку. Не собирайте её поверх старой версии с уже существующей папкой `build`.
2. В верхней панели Visual Studio выберите `Release` и `x64`.
3. Выполните **Build → Rebuild Solution**.
4. Откройте папку `build\Release`.
5. Передавайте только `StalzoneServerBlocker.exe`.

Release-профиль использует статическую библиотеку C++ `/MT`, поэтому устанавливать Microsoft Visual C++ Redistributable на другом компьютере не требуется. Программа предназначена для 64-битных Windows 10/11 и при запуске запрашивает права администратора.

Файлы `Servers.json`, `fonts` и `app.ico` должны оставаться в папке исходного проекта: компилятор ресурсов берёт их оттуда во время сборки и помещает внутрь EXE. Рядом с уже собранным Release EXE они не нужны.

Если после сборки в `build\Release` остались старые `Servers.json`, `fonts`, `app.ico` или `.pdb`, это остатки предыдущей версии. Удалите только старую папку `build` либо распакуйте проект в новую папку и выполните Rebuild ещё раз.

При распространении неподписанного EXE Windows SmartScreen может показать предупреждение. Для устранения предупреждения при публичном распространении требуется сертификат подписи кода.
